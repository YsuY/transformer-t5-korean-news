# pko-T5를 활용한 한국어 뉴스 요약

## 프로젝트 개요

1. Transformer 논문 리뷰 후 Hugging Face에서 제공되는 Transformer 기반 모델을 직접 조사하기
2. 해당 모델을 활용한 NLP 미니 프로젝트를 진행하기

- 이번 과제 모델: T5 계열의 한국어 사전학습 모델인 pko-T5


### T5

T5는 Transformer의 Encoder-Decoder 구조를 기반으로 하며, 다양한 NLP 문제를 Text-to-Text 형태로 통일하여 처리하는 모델이다.

미니 프로젝트에서는 한국어 뉴스 기사와 요약문으로 구성된 데이터셋을 이용하여 pko-T5를 Fine-tuning하고, 입력된 뉴스 기사에서 핵심 내용을 담은 요약문을 생성하는 것을 목표로 하였다.


### 최종 프로젝트:

한국어 뉴스 기사 -> pko-T5 -> 한국어 뉴스 요약문

## 과제 2. Transformer 기반 모델 조사


## 1. 모델 이름

### pko-T5

- pko-T5는 PAUST에서 공개한 한국어 전용 T5 v1.1 기반 모델이다.
- 기본적인 T5의 Transformer Encoder-Decoder 구조와 Text-to-Text 방식을 사용하면서, 한국어 데이터를 이용하여 사전학습된 모델이다.
- pko-T5에는 모델 크기에 따라 다음과 같은 버전이 있다.

| 모델            | 특징                                        |
| `pko-t5-small` | 가장 가벼운 모델로 학습 속도가 빠르고 실습에 적합 |
| `pko-t5-base`  | Small보다 크고 표현력이 높지만 학습 비용도 증가  |
| `pko-t5-large` | 가장 큰 모델로 높은 연산량과 메모리가 필요       |

- 처음에는 `pko-t5-base`를 사용하였으나 CPU 환경에서 Fine-tuning 시간이 매우 길어 반복 실험이 어려웠다.

따라서 최종 프로젝트에서는 `paust/pko-t5-small`을 사용하였다.


----------------------------------------------------------------------



## 2. 모델이 발표된 배경

기존 NLP에서는 번역, 분류, 요약, 질의응답 등 각 Task에 따라 서로 다른 출력 구조를 사용하는 경우가 많았다.
T5는 이러한 다양한 NLP 문제를 하나의 형태로 통일하기 위해 제안되었다.
핵심 아이디어는 모든 NLP 문제를 다음과 같은 형태로 처리하는 것이다.
즉 입력과 출력을 모두 Text로 통일하여 같은 모델 구조로 여러 NLP Task를 처리할 수 있도록 한 것이 T5의 핵심 특징이다.
pko-T5는 이러한 T5 구조를 한국어 환경에서도 사용할 수 있도록 한국어 대규모 데이터를 이용해 사전학습된 모델이다.



----------------------------------------------------------------------



## 3. Encoder / Decoder / Encoder-Decoder 중 어떤 구조인지

- pko-T5는 Encoder-Decoder 구조이다.


입력 Text

        ↓

Encoder

입력 문장의 문맥 표현 생성

        ↓

Decoder

출력 Text 생성


이번 뉴스 요약 프로젝트에서는 다음과 같이 사용된다.

뉴스 기사

        ↓

Encoder

기사 내용과 문맥 표현 생성

        ↓

Decoder

        ↓

뉴스 요약문 생성



### Encoder

- Encoder는 입력된 뉴스 기사 전체를 읽고 Self-Attention을 이용하여 Token 사이의 관계와 문맥 정보를 만든다.
- 뉴스 기사에서 누가 무엇을 했는지, 어떤 사건이 중요한지와 같은 정보를 표현하게 된다.


### Decoder

- Decoder는 Encoder가 만든 정보를 참고하여 요약문을 Token 단위로 생성한다.
- Decoder에서는 다음 Attention이 사용된다.
        - Masked Self-Attention
        - Cross-Attention
- Masked Self-Attention은 아직 생성하지 않은 미래 Token을 미리 볼 수 없도록 한다.
- Cross-Attention은 Decoder가 다음 Token을 생성할 때 Encoder가 만든 뉴스 기사 정보를 참고할 수 있도록 한다.



----------------------------------------------------------------------



## 4. 사전학습 방식

- T5 계열은 Span Corruption 방식으로 사전학습한다.
- Span Corruption은 문장에서 연속된 일부 구간(Span)을 제거한 뒤 모델이 제거된 내용을 다시 복원하도록 학습하는 방식이다.

전체 과정:

원본 Text

        ↓

일부 Span 제거

        ↓

Encoder 입력

        ↓

Decoder

        ↓

제거된 Span 복원

- 이 과정을 반복하면서 모델은 문장의 문맥과 Token 사이의 관계를 학습한다.
- pko-T5는 T5 v1.1 구조를 기반으로 한국어 데이터를 이용해 이러한 사전학습 과정을 수행한 모델이다.



----------------------------------------------------------------------



## 5. 기존 Transformer와 달라진 점


### 기존 Transformer

- 기존 Transformer는 Encoder와 Decoder를 이용한 Sequence-to-Sequence 구조를 제안하였다.
- 대표적으로 기계 번역과 같은 문제에서 입력 Sequence -> 출력 Sequence 형태로 사용되었다.


### T5

- T5는 Transformer의 Encoder-Decoder 구조를 그대로 활용하면서 모든 NLP Task를 Text-to-Text 형태로 통일하였다.
- 따라서 번역뿐 아니라 요약, 분류, 질의응답 등 서로 다른 Task도 같은 모델 구조에서 처리할 수 있다.


### T5 v1.1

- pko-T5의 기반인 T5 v1.1은 기존 T5의 학습 방식과 일부 구조를 개선한 버전이다.

- 특징
        - Feed Forward Network에서 GEGLU 사용
        - 사전학습 과정의 일부 설정 변경
        - 사전학습을 비지도 학습 중심으로 구성
        - Embedding과 출력 Layer의 Parameter Sharing 방식 변경


### pko-T5

- pko-T5는 T5 v1.1 구조를 기반으로 하면서 한국어에 맞게 사전학습된 모델이다.

- 특징
        - 한국어 대규모 데이터로 사전학습
        - 한국어 NLP Task에 활용 가능
        - BBPE(Byte-level BPE) 기반 Tokenizer 사용
        - T5의 Encoder-Decoder 구조와 Text-to-Text 방식 유지



----------------------------------------------------------------------



## 6. 해당 모델이 잘하는 작업

- T5는 입력 Text를 받아 새로운 Text를 생성하는 구조이므로 다양한 NLP Task에 사용할 수 있다.

- 대표적인 작업:
        - 문서 요약
        - 뉴스 요약
        - 기계 번역
        - 질의응답
        - 문장 생성
        - 텍스트 분류
        - 자연어 추론

특히 이번 프로젝트처럼 긴 뉴스 기사에서 핵심 내용을 추출하여 새로운 요약문을 생성하는 Abstractive Summarization에 적합하다.



----------------------------------------------------------------------



## 7. 모델의 장점과 단점

### 장점

1. 다양한 NLP Task를 하나의 구조로 처리할 수 있다.
- T5는 모든 문제를 Text-to-Text 형태로 처리하기 때문에 Task마다 완전히 다른 모델 구조를 만들 필요가 없다.

2. Encoder-Decoder 구조를 이용한 Text 생성이 가능하다.
- Encoder가 입력 문장을 이해하고 Decoder가 새로운 문장을 생성하므로 요약, 번역 등의 생성 Task에 적합하다.

3. 사전학습 모델을 Fine-tuning하여 사용할 수 있다.
- 처음부터 언어 모델 전체를 학습할 필요 없이 이미 학습된 언어 능력을 활용하여 특정 Task에 맞게 추가 학습할 수 있다.

4. pko-T5는 한국어에 특화되어 있다.
- 한국어 데이터를 이용해 사전학습되어 한국어 뉴스 기사와 같은 Task에 활용하기 적합하다.

### 단점

1. 모델 크기에 따라 학습 비용이 크다.
- `pko-t5-base`는 CPU 환경에서 Fine-tuning 시간이 매우 길었다.

- 이번 프로젝트에서는 반복 실험이 가능한 수준으로 학습 시간을 줄이기 위해 최종적으로 `pko-t5-small`을 사용하였다.

2. 긴 입력에는 길이 제한이 있다.
- 뉴스 기사가 설정한 최대 Token 길이보다 길면 뒤쪽 내용이 Truncation될 수 있다.

3. Hallucination이 발생할 수 있다.
- Decoder가 새로운 Text를 생성하는 모델이므로 원문에 존재하지 않는 내용을 생성할 가능성이 있다.

4. 생성 결과의 품질을 하나의 지표만으로 평가하기 어렵다.
- ROUGE 점수가 높더라도 사람이 읽었을 때 핵심 내용이 제대로 포함되지 않을 수 있기 때문에 실제 생성 결과도 함께 확인해야 한다.

## 9. 사용한 모델과 데이터셋 소개

### 사용 모델

- 최종 모델: paust/pko-t5-small

- 처음에는 `paust/pko-t5-base`를 사용하였다.

- 따라서 최종 모델은 더 가벼운 **pko-t5-small**로 변경하였다.

## 10. Tokenizer를 이용한 데이터 전처리

- pko-T5는 문자열을 그대로 계산할 수 없기 때문에 Tokenizer를 이용하여 뉴스 기사와 정답 요약문을 Token ID로 변환하였다.
- 사용 Tokenizer: `T5TokenizerFast`

- 뉴스 기사에는 Task를 구분할 수 있도록 다음 Prefix를 추가하였다.
- `뉴스 요약: ` + 기사 본문

- 입력 데이터 처리: 뉴스 기사 -> "뉴스 요약: " Prefix 추가 -> Tokenizer -> input_ids -> attention_mask
- 정답 데이터 처리: 정답 요약문 -> Tokenizer -> labels

- 최종 설정:

| 항목            | 설정                        |
| 최대 입력 길이   | 256 Token                  |
| 최대 Target 길이 | 128 Token                  |
| Truncation      | 사용                       |
| Padding         | Batch 단위 Dynamic Padding |

- 처음에는 Target 길이를 64 Token으로 설정하였다.
- 하지만 Test 결과에서 일부 모델 요약이 문장 중간에서 잘리는 문제가 확인되어 최종 학습에서는 `MAX_TARGET_LENGTH`와 `MAX_NEW_TOKENS`를 128로 증가시켰다.



----------------------------------------------------------------------



## 11. 사전학습 모델 Fine-tuning

- 사전학습된 pko-T5를 뉴스 기사와 요약문의 관계에 맞게 Fine-tuning하였다.

- 학습 데이터 하나의 형태: 
        1. 뉴스 기사 -> Encoder Input -> pko-T5 -> Decoder -> 예측 요약문
        2. 정답 요약문 -> labels -> 예측 Token과 비교 -> Loss 계산 -> Backpropagation

- 학습 설정:

| 항목                   | 설정                 |
| Model                 | `paust/pko-t5-small` |
| Train Sample          | 3,000                |
| Validation Sample     | 300                  |
| Input Length          | 256                  |
| Target Length         | 128                  |
| Batch Size            | 2                    |
| Gradient Accumulation | 4                    |
| Learning Rate         | 0.00005              |
| Random Seed           | 42                   |
| Optimizer             | AdamW                |

## 12. 학습 과정

- pko-t5-small의 처음 3 Epoch 학습 결과:

| Epoch | Train Loss | Validation Loss |
| 1 | 1.2496 | 0.9485 |
| 2 | 1.0028 | 0.8817 |
| 3 | 0.9204 | 0.8661 |

- Epoch 3까지 Validation Loss가 계속 감소하였기 때문에 추가 학습이 필요하다고 판단하였다.

- 기존 Epoch 3의 Best Model을 불러와 Epoch 4와 5를 추가로 Fine-tuning하였다.
- 추가 학습 결과:

| Epoch | Train Loss | Validation Loss |
| 4 | 0.8628 | 0.8517 |
| 5 | 0.8110 | 0.8522 |

- Epoch 4에서 Validation Loss가 0.8517로 가장 낮게 나타났다.
- Epoch 5에서는 Train Loss가 계속 감소하였지만 Validation Loss는 0.8522로 소폭 증가하였다.
- 따라서 최종 모델은 **Epoch 4 모델**로 선택하였다.

- 최종 학습 결과:

        - Best Epoch: 4  
        - Best Validation Loss: 0.8517

## 13. 성능 평가

- 최종 Best Model을 Test 데이터 300개에 적용하여 성능을 평가하였다.
- 뉴스 요약과 같은 Text 생성 문제이므로 ROUGE를 평가 지표로 사용하였다.
- 사용한 평가 지표:
        - ROUGE-1
        - ROUGE-2
        - ROUGE-L
        - ROUGE-Lsum
- 최종 결과:

| 평가 지표   | 결과    |
| ROUGE-1    | 0.5082 |
| ROUGE-2    | 0.2743 |
| ROUGE-L    | 0.4796 |
| ROUGE-Lsum | 0.4797 |


### ROUGE-1

- ROUGE-1은 모델이 생성한 요약문과 정답 요약문 사이에서 단어 단위의 겹침 정도를 평가한다.
- 결과: ROUGE-1 = 0.5082


### ROUGE-2

- ROUGE-2는 연속된 두 단어 단위의 일치 정도를 평가한다.
- 결과: ROUGE-2 = 0.2743


### ROUGE-L

- ROUGE-L은 모델 요약과 정답 요약에서 공통적으로 나타나는 긴 Sequence를 이용해 문장의 전체적인 흐름과 순서를 평가한다.
- 결과: ROUGE-L = 0.4796

## 14. Test 예측 결과

### 예시 1

- 기사 제목: 아이트로닉스 차량용 복합기능형 졸음 방지 단말기 특허 출원

- 정답 요약:
아이일, 아이트로닉스는 차량용 복합기능형 졸음 방지 단말기 특허를 출원했다고 4일 밝혔으며 신규 특허는 자동차 주행 중 운전자의 졸음운전을 방지하는 상태 검출 기술에 관한 것으로, 해당 단말기는 가시광선 및 근적외선 광원을 조사하는 광원 모듈 운전자의 얼굴 영상을 촬영하는 가시광선 및 근적외선 카메라 차량 실내의 이산화탄소 농도를 측정하는 이산화탄소 센서로 구성됐다.

- 모델 요약: 아이엘사이언스의 자회사 아이트로닉스는 차량용 복합기능형 졸음 방지 단말기 특허를 출원했다고 4일 밝혔다.


### 예시 2

- 정답 요약:

- 모델 요약: 뉴욕증권거래소 NYSE 에서 다우존스 산업평균지수는 전장보다 253.88포인트 0.82% 하락한 30 775.43으로 거래를 마쳤다. 첫 번째와 두 번째 예측에서는 기사의 핵심 내용을 비교적 짧고 자연스럽게 요약하였다. 반면 세 번째 예측에서는 기사 전체의 핵심 주제인 S&P 500의 상반기 부진과 경기침체 우려보다 특정 다우존스 지수 수치에 집중한 결과가 나타났다.
따라서 ROUGE와 같은 정량적인 평가뿐 아니라 실제 생성된 요약문을 함께 확인하는 것이 중요하다.

## 15. 새로운 문장을 직접 입력하여 예측

- 학습 데이터에 없는 새로운 뉴스 형식의 문장을 직접 입력하여 요약 결과를 확인하였다.

- 입력 기사:
서울시는 올해부터 인공지능 기반 교통 신호 시스템을 확대 도입한다고 밝혔다. 해당 시스템은 실시간 교통량과 도로 혼잡도를 분석해 신호 주기를 자동으로 조절하는 방식이다. 서울시는 우선 주요 혼잡 구간을 중심으로 시스템을 적용한 뒤 효과를 분석해 적용 지역을 단계적으로 확대할 계획이다. 이번 사업을 통해 출퇴근 시간대 교통 혼잡과 차량 대기 시간을 줄일 수 있을 것으로 기대하고 있다.

- 모델 요약:
서울시는 올해부터 인공지능 기반 교통 신호 시스템을 확대 도입한다고 밝혔으며 해당 시스템은 실시간 교통량과 도로 혼잡도를 분석해 적용 지역을 단계적으로 확대할 계획이다.

- 모델은 다음 핵심 내용을 요약문에 포함하였다.
        - 인공지능 기반 교통 신호 시스템 확대 도입
        - 실시간 교통량과 도로 혼잡도 분석
        - 적용 지역의 단계적 확대

- 다만 원문 마지막의 교통 혼잡과 차량 대기 시간 감소에 대한 기대 효과는 최종 요약문에서 제외되었다.
- 이를 통해 모델이 새로운 입력에서도 핵심 내용을 이용해 요약문을 생성할 수 있지만 모든 정보를 반드시 포함하지는 않는다는 것을 확인하였다.

## 16. 모델의 문제점 및 개선 방법 분석

### 16-1. 긴 뉴스 기사의 정보 손실

이번 프로젝트에서는 최대 입력 길이를 256 Token으로 설정하였다.

뉴스 기사가 256 Token보다 길면 이후의 내용이 Truncation되므로 중요한 정보가 기사 뒤쪽에 존재할 경우 모델이 해당 내용을 확인할 수 없다.

개선 방법:

- 최대 입력 Token 길이 증가
- 긴 문서를 처리하기에 적합한 모델 사용
- 긴 기사를 여러 구간으로 나누어 처리하는 방식 검토


### 16-2. 일부 핵심 정보가 요약에서 제외될 수 있음

직접 입력 예측에서 교통 신호 시스템 도입과 단계적 확대는 정상적으로 반영되었지만, 교통 혼잡 및 차량 대기시간 감소라는 기대 효과는 제외되었다.

즉 모델이 문서를 압축하는 과정에서 사람이 중요하다고 판단하는 정보 중 일부를 생략할 수 있다.

개선 방법:

- 더 많은 Fine-tuning 데이터 사용
- 학습 데이터의 요약 품질과 일관성 개선
- 입력 길이 및 생성 길이 조정


### 16-3. 기사 전체의 핵심보다 특정 세부 내용에 집중할 수 있음

S&P 500 관련 Test 예측에서는 기사 전체의 핵심 내용보다 다우존스의 특정 하락 수치에 집중하여 요약하였다.

개선 방법:

- 더 많은 뉴스 기사와 요약문으로 Fine-tuning
- 다양한 카테고리의 학습 데이터 활용
- 생성 결과를 사람이 직접 확인하는 정성 평가 추가


### 16-4. Hallucination 가능성

- T5는 Decoder가 새로운 Text를 생성하는 생성형 모델이다. 따라서 원문에 없는 사실이나 표현을 생성할 가능성이 있다.
- 특히 뉴스 요약에서는 사실과 다른 내용을 생성하면 문제가 될 수 있다.
- 개선 방법:
        - 원문과 생성 결과 사이의 사실 일치성 평가
        - 더 많은 고품질 뉴스 요약 데이터 사용
        - 생성 결과 검증 과정 추가


### 16-5. ROUGE만으로 요약 품질을 완전히 판단하기 어려움

- ROUGE는 정답 요약과 생성 요약 사이의 단어나 Sequence 중복 정도를 평가한다.
- 하지만 같은 의미를 다른 표현으로 생성하면 실제로는 좋은 요약이어도 ROUGE 점수가 낮아질 수 있다.
- 또한 ROUGE 점수가 높아도 핵심 내용이 잘못 선택될 가능성이 있다.
- 개선 방법:
        - ROUGE와 실제 생성 결과를 함께 확인
        - 의미 기반 평가 지표 추가
        - 사람이 직접 읽고 평가하는 정성 평가 사용

## 17. Base에서 Small로 모델을 변경한 이유

- 처음에는 `pko-t5-base`로 프로젝트를 진행하였다.

- Base 모델 학습 결과: Best Epoch: 2  / Best Validation Loss: 0.6923
- Test 결과:
        ROUGE-1: 0.4873  
        ROUGE-2: 0.2696  
        ROUGE-L: 0.4677  
        ROUGE-Lsum: 0.4671

- 그러나 CPU 환경에서 Base 모델의 학습 시간이 매우 길었다.
- 일부 Epoch에서는 1시간 이상이 필요했고 반복 실험이나 Parameter 수정 후 재학습이 어려웠다.
- 또한 초기 설정에서 최대 생성 길이가 64 Token으로 설정되어 일부 Test 요약문이 문장 중간에서 잘리는 문제가 있었다.
- 이를 수정하면서 모델도 `pko-t5-small`로 변경하였다.

- Small 모델 결과:
        - 최대 Target 길이 128
        - 최대 생성 길이 128
        - Epoch당 약 20~30분
        - 추가 실험 가능
        - 최종 Test ROUGE 상승

- 최종 Small 결과:

| 평가 지표   | Base   | Small  |
| ROUGE-1    | 0.4873 | 0.5082 |
| ROUGE-2    | 0.2696 | 0.2743 |
| ROUGE-L    | 0.4677 | 0.4796 |
| ROUGE-Lsum | 0.4671 | 0.4797 |

- 이번 실험 조건에서는 Small 모델이 학습 비용을 크게 줄이면서 Test ROUGE에서도 더 높은 결과를 보였다.
- 다만 Base와 Small은 Target 길이와 최종 학습 조건이 완전히 동일하지 않았기 때문에 이 결과만으로 Small 모델이 항상 Base보다 성능이 좋다고 일반화할 수는 없다.
